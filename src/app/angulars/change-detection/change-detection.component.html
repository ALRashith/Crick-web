Angular interview preparation

Change detection

Change detection is Angular's process for checking component state and updating the DOM when that state changes.

Interview answer

Change detection is how Angular notices that a TypeScript value changed and then updates the matching HTML. For example, after a button changes the component's count value, Angular checks the view and renders the new value on screen.

Think of it as a three-step cycle

  1. An event happens: a click, timer, HTTP response, or input change.
  2. Angular checks: it compares the component values used by the template.
  3. The screen updates: Angular changes only the DOM values that are different.

Example: clicking “Increase” changes count from 0 to 1. Angular sees the event, checks the binding, and renders 1 instead of 0.

01

Default strategy

Simple state updates

Angular uses the default strategy unless another strategy is selected. It checks the component tree after events and asynchronous work, which is convenient but can do more checking than a large application needs.

The template value is now {{ defaultCount }}.

count = 0;

increment(): void {
  this.count++;
}

Use when: you want Angular to handle updates automatically with minimal configuration.

02

OnPush strategy

Prefer immutable updates

OnPush improves performance by narrowing checks. With input objects, replace the reference instead of mutating the existing object. A new reference tells Angular that the input changed.

This demo value is now {{ onPushCount }}.

@Component({
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class CardComponent {
  user = { name: 'Asha' };

  rename(): void {
    this.user = { ...this.user, name: 'Maya' };
  }
}

Use when: you want predictable checks and better performance in reusable components.

03

Manual control

Detect only when needed

Inject ChangeDetectorRef when a specialized workflow needs explicit control. detectChanges() checks this view immediately after your code changes a value.

The manually checked value is {{ manualCount }}.

constructor(private cdr: ChangeDetectorRef) {}

updateView(): void {
  this.value++;
  this.cdr.detectChanges();
}

Use when: you intentionally control when a view is checked, such as a high-frequency update.

Key tradeoff Use OnPush by default for predictable, efficient components. Be careful with direct mutation because the object reference does not change.
